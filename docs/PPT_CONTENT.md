# 발표 PPT 콘텐츠 — 슬라이드 구성안 + 대본

이 문서는 8/20 최종 발표용 PPT에 담을 내용을 슬라이드 단위로 정리한 초안입니다. 실제 PowerPoint 파일에는
이 문서를 보면서 직접 옮겨 담으면 됩니다. 심사 기준 4개(**문제 정의 / 현업 적용 / AI 활용 능력 / 전달력**)에
맞춰 어느 슬라이드가 어느 기준을 겨냥하는지 `[심사: ...]` 표시를 붙여뒀습니다.

기존 `발표피피티/16팀_3주차_프로젝트 최종발표 초안.pptx`(8/5 작성본)의 목차 골격을 이어받되, gate/metal
공정 추가 이후 최신 상태로 채우고 AI 활용 슬라이드를 분리·구체화했습니다.

각 기능의 자세한 설명은 [`FEATURE_GUIDE.md`](FEATURE_GUIDE.md), 데이터/모델 근거 수치는
[`PROJECT_OVERVIEW.md`](../PROJECT_OVERVIEW.md)를 참고해서 채웠습니다.

## 슬라이드 3 — `[심사: 문제 정의]` 프로젝트 배경

**핵심 문구**: 감이 아닌 데이터로 판단한다

**대본**:
지금까지 반도체 Etch 공정 평가는 엔지니어 개인의 경험과 판단에 크게 의존해왔습니다. 이 때문에 평가하는
사람에 따라 결과 해석이 달라지고, 원하는 품질에 도달할 때까지 Recipe를 몇 번이고 다시 시도해야 하는
경우가 많았습니다. 저희는 이 반복 횟수(N회 재작업)를 줄이는 것을 목표로 프로젝트를 시작했습니다.

## 슬라이드 4 — `[심사: 문제 정의→해결]` 핵심 아이디어

**핵심 문구**: 데이터 기반 예측 → 종합 점수화 → 최적 조건 추천, 3단계로 이어지는 흐름

**대본**:
저희가 만든 시스템은 세 가지 축으로 움직입니다. 첫째, 과거 실측 데이터로 학습한 AI 모델이 Recipe 조건의
결과를 미리 예측합니다. 둘째, Pass Rate·Uniformity·목표 근접도를 하나의 종합 품질 점수로 합쳐서
직관적으로 비교할 수 있게 합니다. 셋째, 목표 대비 평가부터 최적 Recipe 추천, 파라미터 조정 제안까지
자동으로 이어집니다.

## 슬라이드 5 — 시스템 개요

**핵심 문구**: 4개 공정(Isolation / Trench / Gate PolySi / Metal Al) 전부 지원

**대본**:
처음엔 Isolation 공정 하나로 시작했지만, 같은 방법론을 그대로 재사용해서 Trench, Gate, Metal까지 총 4개
공정으로 확장했습니다. 공정마다 파라미터 개수와 Stage 구조는 다르지만, 데이터 검증부터 모델 학습, 대시보드
연결까지 동일한 파이프라인을 사용합니다.

## 슬라이드 6~9 — `[심사: 현업 적용]` 주요 기능 소개

각 기능마다 1슬라이드, 화면 스크린샷 + 아래 요약 문구로 구성 (자세한 내용은 `FEATURE_GUIDE.md` 참고).

### 6. 공정 예측 · 평가 · 추천
Recipe 조건 또는 목표 품질을 입력하면 AI가 예측 → 점수화 → 파라미터 조정까지 추천. 목표 모드 / Recipe
입력 모드 2가지로 상황에 맞게 사용.

### 7. Process Dashboard
실측 데이터를 Recipe(Rev)별로 한눈에 비교. Rev별 스코어링 순위, Wafer 단면 Profile, Zone별 분석까지
제공.

### 8. Parameter 변경 이력 조회
Recipe가 개선되어온 과정을 파라미터 변경 단위로 추적. 어떤 변경이 품질을 얼마나 바꿨는지 확인 가능.

### 9. 신규 공정 품질 예측
아직 데이터가 없는 새 공정도 기존 유사 공정 참고값으로 미리 가늠해볼 수 있는 확장 기능.

**현업 적용 포인트(대본 공통 삽입)**: 이 네 가지 기능은 엔지니어가 실제로 Recipe를 검토·개선하는 흐름
(예측 → 평가 → 이력 추적 → 신규 확장) 그대로를 따라가도록 설계했습니다. 그래서 별도 교육 없이도 기존
업무 순서 그대로 사용할 수 있습니다.

## 슬라이드 10 — `[심사: AI 활용 능력 — ①]` 머신러닝 모델 학습

**핵심 문구**: 항목마다 RandomForest / XGBoost 모델을 학습시키고, 검증 결과로 자동 선택

**대본**:
품질 예측에는 실제로 학습시킨 RandomForest와 XGBoost 모델을 사용합니다. Top/Mid/Bottom CD, Depth,
Defect 개수·심각도, Spec Pass 여부까지 항목별로 따로 모델을 학습시키고, "한 번도 안 써본 Recipe
조합"에 대한 일반화 성능(whole-recipe-holdout 교차검증)을 기준으로 가장 성능이 좋은 모델을 자동으로
골랐습니다. 사람이 임의로 고른 게 아니라 검증 점수로 선정한 것이라, isolation은 대부분 RandomForest·
XGBoost가 선택됐고 trench·gate·metal은 데이터 특성에 따라 MLP가 선택된 항목도 일부 있습니다.
4개 공정 전부 244/236/231/236장의 실측 Wafer 데이터로 학습했습니다.

## 슬라이드 11 — `[심사: AI 활용 능력 — ②]` 생성형 AI(클로드 코드) 활용

**핵심 문구**: 비전공자가 클로드 코드(생성형 AI)로 대시보드와 머신러닝 파이프라인을 직접 구축

**대본**:
저는 비전공자지만, 생성형 AI 코딩 도구인 클로드 코드를 활용해서 이 시스템을 실제로 구축했습니다. AI가
코드를 대신 짜준 게 전부가 아니라, 데이터 이상치 발견, 학습 파이프라인 설계, 실제 사용해보면서 찾은 버그
수정까지 사람이 판단하고 AI가 구현하는 방식으로 작업했습니다. 예를 들어 "목표 품질을 바꿔도 추천 결과가
그대로인" 버그나 "결측치가 만점으로 둔갑하는" 버그처럼, 실제로 써보지 않으면 알기 어려운 문제들을
직접 테스트해서 찾아내고 수정했습니다. 생성형 AI 덕분에 비전공자도 아이디어를 실제 동작하는 시스템으로
빠르게 구현할 수 있었습니다.

## 슬라이드 12 — 기대 효과

**핵심 문구**: 평가 반복 횟수 감소, 개인 경험 의존 → 데이터 기반 의사결정 전환

**대본**:
이 시스템을 쓰면 Recipe를 실제로 시도해보기 전에 결과를 미리 가늠할 수 있어서, 목표에 도달하기까지의
재작업 횟수를 줄일 수 있습니다. 또한 평가 기준이 개인 경험이 아니라 데이터와 모델로 통일되기 때문에,
누가 평가하든 일관된 결과를 얻을 수 있습니다.

## 슬라이드 13 — 한계와 다음 단계

**핵심 문구**: 정직하게 밝히는 현재 한계

**대본**:
관측된 Recipe가 공정당 16개뿐이고 순차적으로 변경되어온 이력이라, 파라미터 간 인과관계까지는 알 수
없고 연관성만 해석할 수 있습니다. 신규 공정 품질 예측 기능도 아직은 진짜 예측이 아니라 유사 공정 참고값
수준입니다. 다음 단계로는 신규 공정 온보딩 자동화, 더 많은 Recipe 데이터 확보를 통한 예측 신뢰도 향상을
계획하고 있습니다.
